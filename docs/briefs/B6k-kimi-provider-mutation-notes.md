# B6k Kimi OAuth provider mutation notes

Every mutation below has a runtime observer. “Expected RUNTIME failure” means
the named test fails by assertion, typed error, or timeout; a compile-only
failure is not the claimed evidence.

| Production mutation | Runtime observer | Expected RUNTIME failure |
|---|---|---|
| Add PKCE/client-secret fields, omit any required `X-Msh-*` header, or regenerate the persisted UUID. | `haider-daemon::oauth::tests::device_flow_polls_to_tokens_with_required_msh_headers` | The fixture rejects the exact form, a header/device ID differs, or the decoded bundle/refresh threshold changes. |
| Stop the production runner at `authorization_pending`, ignore `slow_down`, or add less than five seconds to its interval. | `haider-daemon::oauth::tests::device_flow_runner_continues_and_honors_slow_down_interval` | The coordinator never becomes ready or reaches the third poll before the pinned six-second gate. |
| Replace the physical-vault alias lease with a broker-local gate, move the vault re-read outside the lease, release before atomic persistence, or replay generation N after N+1 landed. | `haider-accounts::file_vault_tests::independent_file_vaults_share_the_refresh_rotation_lease` and `haider-daemon::oauth::tests::concurrent_refreshers_never_destroy_the_rotated_token` | Both independent vaults enter the critical section, the fake endpoint sees two generation-N refreshes, a contender fails instead of adopting N+1, or the stored generation/token differs. |
| Send a rotating request before persisting uncertainty, clear uncertainty after an ambiguous/malformed response, or let an actor-completion loss expose the old token again. | `haider-daemon::oauth::tests::malformed_rotating_success_never_leaves_the_old_token_replayable` | The permanent marker is absent, the successor contacts the endpoint, or the old refresh token is replayed. |
| Release rotated access before `ApplyOAuthRefresh` durably commits, omit the directory sync, or accept a torn/stale apply. | `haider-daemon::oauth::tests::{concurrent_refreshers_never_destroy_the_rotated_token,concurrent_refresh_is_single_flight_rotates_and_persists_before_return,refresh_vault_failure_never_returns_rotated_access}` and `haider-accounts::file_vault_tests::put_then_resolve_returns_the_exact_secret` | A resource observes access before durability, a failed write releases rotated access, or the vault does not contain the complete replacement. |
| Drop the 300-second rejected-token tombstone, keep it only in process memory, or replay a terminally rejected rotating token. | `haider-daemon::oauth::tests::rejected_refresh_tombstones_and_surfaces_typed_relogin` | A second independent broker performs another refresh POST, the persisted rejection deadline is absent, or the error lacks `oauth_relogin_required`. |
| Use the legacy 30-second skew for Kimi, fail to persist the provider threshold, refresh an already-rotated generation after a stale 401, or remove the single forced refresh/retry fence. | `haider-daemon::oauth::tests::{device_flow_polls_to_tokens_with_required_msh_headers,forced_401_reread_adopts_already_rotated_access_without_refresh_post}` and `haider-core/tests/runtime_tests.rs::rotation_is_once_pre_first_event_and_durable_before_the_alternate` | The threshold is outside `remaining < max(300s, expires_in/2)`, a stale 401 contacts the refresh endpoint instead of adopting the durable access token, or attempt resolution occurs more than once within the logical turn. |
| Treat refresh 429/5xx as terminal, remove bounded exponential backoff, or retry an ambiguous transport failure as though it were an explicit retryable status. | `haider-daemon::oauth::tests::{kimi_refresh_backoff_is_bounded_to_explicit_retryable_statuses,transient_refresh_fails_closed_for_leader_and_waiter_after_uncertain_request,no_secret_bytes_in_errors_journal_or_logs}` | The delay/count policy differs, the error loses fail-closed behavior, or raw response/token bytes enter the public failure. |
| Route Kimi through generic `max_tokens`, omit Bearer, enable top-level `thinking` by default, encode its SDK `extra_body` seam as a nested wire field, or expose Kimi thinking options on another compatible provider. | `haider-provider::openai::tests::kimi_requests_use_bearer_and_max_completion_tokens` | The exact request/header golden changes, thinking appears by default or at the wrong JSON level, or the provider-specific seam stops rejecting the generic dialect. |
| Infer Kimi capabilities from model names, invent stronger tool semantics, or ignore declared vision/thinking flags. | `haider-provider::openai::tests::kimi_capabilities_are_derived_only_from_catalog_flags` | The context/vision/thinking values differ from the fixture or parallel/streaming tool semantics become supported. |
| Parse Kimi through the generic compatible source, ignore `context_length`, publish `protocol:"anthropic"`, or invent absent flags. | `haider-provider/tests/catalog_tests.rs::models_catalog_parses_context_length_and_skips_anthropic_protocol` | Context/flags differ or the deferred Anthropic-protocol residual appears in the published inventory. |
| Serialize the new catalog extension as `null` on old sources or reorder/change an existing cache row. | `haider-provider/tests/catalog_tests.rs::legacy_catalog_rows_serialize_byte_identically` | The pinned pre-B6k JSON row gains or changes bytes. |
| Register Kimi as custom/API-key/Responses, widen its credential-bearing origin beyond the exact chat/models endpoints, or bypass the real Chat Completions adapter during validation. | `haider-daemon::provider_registry::provider_registry_tests::kimi_oauth_is_a_builtin_chat_completions_subscription_provider`, `haider-daemon::oauth::tests::sanctioned_oauth_table_has_exact_owner_grants_and_precise_reasons`, `haider-provider::openai::tests::kimi_fixed_origin_allows_exact_chat_and_models_endpoints`, and the one-token Kimi validator path | Registry auth/family/origin differs, an extra endpoint is accepted, sanctioned metadata changes, or validation no longer sends a one-token request through the production adapter. |
| Make device status mandatory to older readers, remove the advertised feature, reorder prior transcript frames, or put callback/token material into a status. | `haider-rpc/tests/wire_golden_tests.rs::{compact_ws_bodies_and_length_prefixed_uds_streams_are_golden,oauth_methods_features_and_status_are_additive_unknown_tolerant,oauth_status_shapes_cannot_carry_callback_or_token_secrets}` and `haider-daemon::connection_tests::welcome_features_pin_served_management_families` | Prior bytes move, a pre-device reader rejects rather than maps to unknown, the feature disappears, or a forbidden secret coordinate serializes. |
| Include access/refresh tokens or bounded endpoint bodies in errors, logs, or a journal record. | `haider-daemon::oauth::tests::no_secret_bytes_in_errors_journal_or_logs`, existing callback/error redaction tests, and `haider-accounts::oauth::tests::token_bundle_debug_redacts_both_tokens` | A sentinel appears in formatted public state or token bundle formatting. |

The HTTP fixture laws use loopback TCP. In restricted macOS sandboxes that
prohibit `bind(2)`, they compile but stop at fixture setup with
`Operation not permitted`; they execute normally in the workspace/CI runtime
where loopback fixtures are permitted.
