# B2a branch-core mutation notes

Every mutation below has a runtime observer. “Expected RUNTIME failure” means
the named test fails by assertion, timeout, or typed protocol/store error; a
compile-only failure is not the claimed evidence.

| Production mutation | Runtime observer | Expected RUNTIME failure |
|---|---|---|
| Split branch row, `BranchCreated` fact, and command receipt across transactions; validate mutable state before receipt replay; or let a changed fork/name body reuse one command id. | `haider-store/tests/branch_tests.rs::branch_create_receipt_event_and_registry_are_one_atomic_fact` and `haider-daemon::session_hub_private_tests::branch_create_receipt_replays_before_attachment_and_generation_validation` | A forced late event-id collision leaves partial durable state, restart loses the original response coordinates, a changed body replays, or RPC replay incorrectly requires a current generation/control attachment. |
| Validate fork node and sequence independently; ignore the session/declared source lineage/root-agent ownership; permit a live turn boundary; or require every fork point to be unique. | `haider-store/tests/branch_tests.rs::fork_coordinates_are_exact_lineage_root_agent_and_stable` | A cross-session, fabricated, mismatched, sibling, child-agent, or nonterminal coordinate commits, or a second legal fork of the same node is refused. |
| Parent branch turns from the session-global last node, omit their branch stamp, update the branch head outside acceptance, or mint a concrete main id. | `haider-store/tests/branch_tests.rs::branch_turns_parent_stamp_and_advance_only_the_selected_head` | The accepted parent/head/scope differs from the selected named ref, or legacy main ceases to be `None`. |
| Admit overlapping nonterminal turns on one named ref, or serialize all branches behind one mutable branch head. | `haider-store/tests/branch_tests.rs::a_named_branch_serializes_nonterminal_turns_but_other_branches_may_queue` | A second run advances branch A before its first assistant commits, or branch B can no longer queue independently. |

| Let an intent activate compaction before its node commits, or recover an interrupted compaction on main. | `haider-daemon::context_core_tests::crash_after_compaction_intent_abandons_without_changing_the_prompt` | Reopen changes prompt bytes, a compaction node appears, or the recovery terminal is not on the original branch. |
| Remove the conservative session-global compaction head CAS. | `haider-daemon::session_hub_private_tests::worker_head_cas_rejects_a_compaction_batch_after_history_advances` | An intervening sibling/session append no longer forces a safe retry and the stale batch commits. |

| Remove `branch_create_v1`, change legacy main request/response bytes, or omit the additive branch request/response/fact shapes. | `haider-daemon::connection_tests::welcome_features_pin_served_management_families`, `haider-rpc/tests/wire_golden_tests.rs`, and `haider-protocol/tests/golden_tests.rs::golden_branch_created_fact` | Feature discovery or an existing/additive wire golden changes. |

The `None` sites left in production are intentional type/scope boundaries:
session aggregates, the implicit main branch, delegated child sessions’ own
main branch, and direct shell execution (which has no branch coordinate in
B2a). They are not mutable active-branch lookups.

Named turn/compaction responses use additive
`turn.submit.on_branch`/`session.compact.on_branch` tags. Main responses retain
their historical tags and bytes, so the excluded `haider-tui` client continues
to decode legacy traffic without source changes; the branch feature gate tells
new clients when the additive response forms are available.
