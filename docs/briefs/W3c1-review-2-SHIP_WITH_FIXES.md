NEW-MECHANISM ATTACK REPORT

**(a) Transition gate at WorkerAppend.** Legitimate-Done-racing-cancel traced end-to-end: worker completes; hub actor serializes CancelTurn first; `commit_state(Done)` rejected (RunNotActive); core falls to `errored_state_outcome` → `commit_terminal_error` batch [RunFailed, Errored] also rejected (atomic, nothing partial commits); core returns an in-memory Errored outcome; supervisor re-reads durable truth (Cancelling) → `cancelled_resumption_payloads` → Cancelled. The worker observes a store error, never wedges; the run terminalizes Cancelled; the wire client that was told "cancellation accepted" sees exactly that durable terminal — this is the R5 law, not a lie (streamed items remain durable). Done-before-cancel: cancel_turn transactionally reports AlreadyTerminal. Authoritative site is single for live workers (every worker path — supervisor, tools, broker journal sink, manager terminalizers, drain sweep — appends through a lease → WorkerAppend → `append_worker`); startup recovery/CLI remain the documented discipline-held no-hub class. Non-terminal-forever: only if effect reconciliation or resumption reduction fails on a store error — supervisor exits with terminal fenced (correct: never synthesize Cancelled over an unreconciled Dispatched), run stays Cancelling until next submit's durable-cancellation sweep or restart recovery. Bounded, comment-documented. One real defect found on these paths: the aggregate-Idle bypass (NF-1).

**(b) Per-item recovery degradation.** The C4a fatal class stays fatal: pre-Ready effect reconciliation and turn-reduction errors still abort startup; corrupt session metadata is StoreCorrupt (decode error ≠ missing — `session_metadata()?` propagates), distinct from legacy-`{}`-metadata which terminalizes; degradation-of-degradation (terminalization append fails) propagates through recovery_ready → startup Err → fatal. No loop: successful degradation leaves a terminal run the next start skips; persistent store failure is correctly a crash-loop. Menu closure uniform: every terminalization path routes through `interrupted_terminal_payloads` (item close + MenuClosed + RunFailed + terminal), verified by the revoked-credential and panic-with-open-menu tests. Residual: a journal-corrupt-payload session could fail prompt-compile and be degraded per-run rather than halting the daemon — defensible under "terminalize what cannot resume" since both pre-Ready corruption scans still run first; noting only.
