# T-wave research: Haider talk/dictation (local Whisper + Deepgram), independent of Diff Forge ADE

Legend: [V] = verified by reading code or current docs; [I] = inferred. All paths absolute. Research only — no repo was modified.

## VERDICT

- The Diff Forge ADE does NOT embed whisper as a library. It shells out to the **whisper.cpp CLI** (`whisper-cli`/`main`/`whisper` binary) against **ggml `.bin` models downloaded from Hugging Face into `<data_dir>/DiffForge/whisper/`** (macOS: `~/Library/Application Support/DiffForge/whisper/`). [V] Haider can share models **byte-for-byte** by resolving the exact same directory and filenames (`ggml-base.en.bin` etc.) and honoring the same `selected-model.txt` sidecar — while keeping its own engine process. No linking of whisper.cpp into the Haider binary is required (a big release-binary win); reproduce the "runtime discovery + Homebrew/zip install" pattern instead.
- The ADE's Deepgram path is a **direct WebSocket to `wss://api.deepgram.com/v1/listen`** with `model=nova-3` **hardcoded** — there is **no model-listing call anywhere in the ADE** [V]. Haider's "fetch models, select" requirement is *new* functionality; the public `GET https://api.deepgram.com/v1/models` endpoint exists, needs only the API key, and returns exactly the metadata needed (name, languages, `streaming` flag) [V-docs].
- The ADE stores the Deepgram key in webview `localStorage` (`diffforge.audio.deepgramApiKey`) — weak precedent; Haider should do better (its own secrets store / keychain pattern).
- Haider split: **audio capture + whisper.cpp spawn + Deepgram WS live in the daemon/agent-host process; the TUI renders the wave and receives transcript frames over the existing wire protocol.** macOS mic TCC will attribute to whichever process opens the mic (terminal app if TUI-spawned — see RISKS).

**Download mechanics** (`download_whisper_model` command, `audio.rs:9710-9915`): serialized behind an async mutex; streamed reqwest GET → `<file>.download` temp; progress events `forge-audio-model-download-progress` with `{state: starting|downloading|runtime|runtime-missing|done, model_id, downloaded_bytes, total_bytes, percent, message}` (`lib.rs:402`, struct usage throughout); **sha256 verified before rename** (`audio.rs:9789-9797`); 900s timeout (`lib.rs:386`). `select_whisper_model` just rewrites `selected-model.txt` (`audio.rs:9917-9930`); `uninstall_whisper_model` removes the whole dir (`audio.rs:9932-9953`).

**Inference invocation** (`transcribe_whisper_audio_for`, `audio.rs:4514-4775`; partial variant `audio.rs:4777-4931`):

- Input contract: 16 kHz mono 16-bit PCM WAV, written to `recordings/`, max 32 MiB (`WHISPER_MAX_AUDIO_BYTES`, `lib.rs:387`), capture cap 900 s (`lib.rs:408`).
- Args: `-m <model> -f <wav> -l en -t <threads> -nt -np -bo 1 -bs 1 -nf` + optional `--prompt <bias terms>` (voice-dictionary biasing) — `audio.rs:4627-4647`. Threads = `available_parallelism` clamped 4–8 (`audio.rs:4489-4494`), partials clamp to ≤4 (`audio.rs:4838`). `-nt` no timestamps, `-np` no prints, greedy best-of-1/beam-1, `-nf` no temperature fallback → latency-optimized. Transcript read from **stdout**; 180 s timeout (`lib.rs:388`); cancellable (generation counter, `audio.rs:4666-4675`).
- Warm cache: model file page-cache pre-read once per path+size (`WhisperCliWarmCache`, `audio.rs:423-524`) — no persistent process; **every chunk is a fresh whisper-cli spawn**.
- Streaming partials ("pseudo-streaming"): a partial session accumulates mic audio and cuts chunks on silence ≥750 ms once ≥10 s buffered (max 35 s force-cut) (`WHISPER_PARTIAL_*`, `lib.rs:410-414`); each chunk is transcribed batch-style and the session emits **cumulative assembled text** via event `forge-audio-realtime-transcript` `{provider:"whisper-local", session_id, chunk_index, text, is_final, speech_final:true, audio_ms}` (`audio.rs:5099-5120`, session loop `audio.rs:5122-5189`; commands `start/stop_local_whisper_partial_transcription` `audio.rs:9984-10130`).
- Resampling: linear-interpolation to 16 kHz (`resample_whisper_audio_to_16khz`, `audio.rs:2758-2789`); hand-rolled WAV encoder (`encode_native_wav`, `audio.rs:2791-2817`).
- Hallucination policy (`WhisperTranscriptPolicy`, defaults `audio.rs:4196-4217`, JSON override compiled in from `src-tauri/whisper-transcript-policy.json` via `include_str!` `audio.rs:4219-4245`): drop transcript if audio <900 ms, RMS <0.01, peak <0.02; suppress bracketed markers (`[BLANK_AUDIO]`, `[SILENCE]`, …) ≤24 chars; suppress the classic low-energy "you" hallucination (≤4 chars/1 word). Language: hardcoded `-l en` for local whisper (only `.en` models are offered).
- stderr warm-up noise filtered by prefix (`whisper_init`, `ggml_`, …) — `audio.rs:4114-4130`.

### A2. Mic capture

- Engine: **dedicated input-worker thread** owning the stream, command-channel driven (`NativeAudioCommand`, request/response with 15s timeouts — `audio.rs:814-883`). Two backends (`NativeAudioStreamHandle`/`NativeAudioEngine`, `audio.rs:628-664`):
  - macOS preferred: **VoiceProcessingIO AudioUnit** (system echo canceller; agent can't hear TTS), client-side rate 48 kHz (`MACOS_VOICE_PROCESSING_SAMPLE_RATE`, `audio.rs:2161-2165`), bypass-gate API for parking the DSP (`audio.rs:666-679`).
  - Fallback/other OS: **cpal 0.15** (`cpal::default_host`, device-by-id `audio.rs:1455-1560`), all sample formats converted to f32 mono (`audio.rs:2613-2750`, mono mix `audio.rs:1740-1750`).
- Capture pipeline keeps a rolling 3 s standby buffer (`AUDIO_BUFFER_MAX_SECONDS`, `lib.rs:405`) with 500 ms pre-roll on record start (`lib.rs:409`); mic runs "warm" on standby.
- Consumers: (a) batch capture → 16 kHz WAV for whisper; (b) partial-chunk channel; (c) realtime byte channel — f32 → **i16 LE PCM** (`audio.rs:1755-1765`) at the *native* session rate, fed to Deepgram/cloud sockets.
- Level/waveform surfacing to UI: event `forge-audio-input-stats` (`lib.rs:403`) emitted every **60 ms (~17 fps) while recording/streaming, 1000 ms on standby** (`lib.rs:415-422`, gate `audio.rs:2096-2107`), payload `AudioInputStats {device_id, engine, echo_cancellation, rms, peak, buffer_ms, frequency_bands, time_domain_samples}` (`audio.rs:2122-2132`):
  - `time_domain_samples`: **256-point envelope** from the last 768 samples — windowed RMS·0.78 + peak·0.22, mean-removed, clamped 0..1 (`native_audio_envelope_samples`, `audio.rs:1689-1738`; window consts `lib.rs:429-430`).
  - `frequency_bands`: 24 log-spaced bands, 90–4200 Hz, dB-normalized −78..−24 (consts `lib.rs:423-428`, `native_audio_frequency_bands` `audio.rs:1634`).
- UI smoothing recipe worth stealing (voice ring, `src/terminals/TerminalView.jsx:13870-14048`): per-point asymmetric smoothing (attack 0.5, decay 0.13), noise-floor auto-calibration on activation, spatial smoothing pass, rAF-driven with idle fallback.
- Watchdogs: digital-zero / stalled-callback detection (`NativeAudioShared.digital_zero_started_at`, `last_callback_at`, `audio.rs:604-625`) — the memory's "Discord VPIO conflict" resilience lives here [I: exact watchdog policy not re-read this pass].

## PART B — Deepgram public API (verified against live docs, fetched 2026-08-05)

All [V] against cited URLs unless marked.

1. **Auth**: API keys → `Authorization: Token <KEY>` for both REST and WS handshake (the only documented scheme for keys). Short-lived JWTs from `POST /v1/auth/grant` use `Bearer <JWT>` (grant: optional `{"ttl_seconds": n}`, default 30 s, returns `{access_token, expires_in}`). Scheme is tied to credential type, not interchangeable. https://developers.deepgram.com/reference/authentication , https://developers.deepgram.com/guides/fundamentals/token-based-authentication
2. **Models listing**: `GET https://api.deepgram.com/v1/models` — **exists, API key only, no project id required**. Query `include_outdated` (bool). Response `{"stt":[...], "tts":[...]}`; per-stt-model fields: `name`, `canonical_name`, `architecture`, `languages[]`, `version`, `uuid`, `batch` (bool), **`streaming` (bool)**, `formatted_output` (bool). Project-scoped variant `GET /v1/projects/{id}/models` adds non-public/custom models. https://developers.deepgram.com/reference/manage/models/list — **This is exactly what Haider's "accept key → fetch models → select" flow needs; filter on `streaming:true` for dictation.**
3. **Streaming WS** `wss://api.deepgram.com/v1/listen`: params `encoding` (`linear16`, also linear32/flac/alaw/mulaw/opus/…), `sample_rate`, `channels` (default 1), `interim_results` (default false), `endpointing` (ms, default 10, or `false`), `vad_events` (→ `SpeechStarted`), `utterance_end_ms` (1000–5000, **requires `interim_results=true`**, → `UtteranceEnd` messages), `smart_format`, `punctuate`, `language`, `model`, `keyterm`, `diarize`, etc. Audio = binary WS frames of raw PCM. Server messages by `type`: `Results` (`is_final`, `speech_final`, `channel.alternatives[]`), `Metadata`, `SpeechStarted`, `UtteranceEnd`. Text control frames: `{"type":"KeepAlive"}` every 3–5 s (10 s silence closes with NET-0001), `{"type":"Finalize"}` (flush), `{"type":"CloseStream"}` (final results then close). Browser-style auth via subprotocol `["token", key]` also documented (irrelevant for Haider's native client). https://developers.deepgram.com/reference/speech-to-text/listen-streaming , /docs/audio-keep-alive , /docs/finalize , /docs/close-stream , /docs/interim-results , /docs/endpointing , /docs/utterance-end
4. **Prerecorded REST** `POST https://api.deepgram.com/v1/listen`: JSON body `{"url": …}` or raw binary body with audio content-type; same param family + batch-only extras (`summarize`, `paragraphs`, `utterances`, `filler_words`, …). Response: `metadata` + `results.channels[].alternatives[]`. Useful as a no-streaming fallback and for key/model smoke tests. https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded
5. **Current models (2026)**: `nova-3` (=`nova-3-general`), `nova-3-medical` — batch+streaming; `nova-2` + domain variants; **Flux** (`flux-general-en`, `flux-general-multi`) — conversational turn-based, **only on `wss://api.deepgram.com/v2/listen`** (will NOT work on /v1/listen); Whisper Cloud (`whisper-tiny…whisper-large`) — **prerecorded only, no streaming**. https://developers.deepgram.com/docs/models-languages-overview , /docs/flux/quickstart , /docs/deepgram-whisper-cloud — Implication: if model list UX lets users pick `whisper-*`, dictation must route via REST batch, or hide non-streaming models; keep Flux out of scope (it's the /voice conversational play later).
6. **Pricing** (pay-as-you-go, https://deepgram.com/pricing): Nova-3 mono **$0.0048/min streaming, $0.0077/min prerecorded**; Nova-3 multi $0.0058/$0.0092; Flux $0.0065–0.0078/min. [I on exactness: page shows promo streaming rates; re-check before hardcoding any price copy.]
7. **Key validation ping**: **`GET https://api.deepgram.com/v1/auth/token`** with `Token <key>` — Deepgram's own documented quick validity test, zero transcription cost. https://developers.deepgram.com/guides/fundamentals/authenticating . (`GET /v1/models` also works with a bare key and doubles as the model fetch — validate + populate in one call. [I])

## PART C — Haider integration sketch

Grounded by read-only recon of `/Users/rizzist/haider-run/haider-agent` (workspace v0.0.67, rust 1.95, ~217k LOC; `Cargo.toml:3-23`). All anchors below verified in-code by the recon pass unless tagged [I].

### C0. Where things run today

- Two processes: `haider` (TUI client; crate `haider-cli` → binary, TUI logic in `crates/haider-tui`) and `haiderd` (daemon; `crates/haider-daemond` thin entry over `crates/haider-daemon`). Transport: Unix domain socket `<runtime_dir>/haider-<blake3-32hex>.sock` (`crates/haider-client/src/profile.rs:205-221`). **No launchd** — the daemon is auto-spawned by the TUI as a detached sibling executable (`process_group(0)`, singleton via store lock; `crates/haider-client/src/spawn.rs:242-423`, `6-14`). [V]
- **Placement decision (the big one):** mic capture must live in a process that can hold the macOS mic TCC grant. For a terminal-launched CLI, TCC attributes the grant to the *responsible process* — the terminal app — for either binary; but `haiderd` is detached and outlives the terminal, making daemon-resident capture fragile (grant attribution to a defunct responsible process). **Recommendation: capture AND the STT engine live in the TUI process (`haider`)**, packaged as a new workspace crate `haider-stt` used by `haider-tui`. This is the cheapest correct integration: zero wire changes, waveform data never crosses IPC, transcript commits are a local composer call. The daemon stays involved only for secret storage (Deepgram key in the profile vault) via one small UDS-only RPC. [I — architecture recommendation; process facts V]
  - Alternative (only if `/voice` later demands daemon-resident audio): TUI captures PCM and streams chunks to a daemon engine over new frames. UDS handles 48 kHz×2 B ≈ 96 KB/s trivially against the 8 MiB frame limit (`crates/haider-rpc/src/frame.rs:24-29`), but it buys the full feature/frame ceremony below for no dictation-visible gain. [I]

## RISKS

1. **macOS mic TCC for a terminal app** [V mechanics / I severity]: the mic prompt will name the *terminal* (Terminal.app, iTerm2, Ghostty…), not Haider — users must grant per-terminal-app; there is no Info.plist usage string for a bare CLI. Denied/ungranted mic shows up as silent zeros or stream errors — port the ADE's digital-zero watchdog idea (`NativeAudioShared.digital_zero_started_at`, `audio.rs:604-625`) and surface a "grant mic to your terminal in System Settings → Privacy" hint. Daemon-resident capture would be worse (detached process, responsible-process attribution to a possibly-dead terminal) — another reason for TUI-resident capture. SSH/remote sessions have no mic: detect and degrade with a clear message.
2. **Shared model dir hazards** [V]: the ADE's `uninstall_whisper_model` deletes the entire `whisper/` dir (`audio.rs:9932-9953`) — Haider must treat model files as evictable at any moment (graceful "model missing — reinstall?" at spawn, never cached-open file handles). Disk: 74–465 MB per model; download timeout 900 s; always sha256-verify (table above) and install via temp+rename.
3. **whisper.cpp runtime availability** [V]: CLI-spawn keeps our release binary clean (no ggml/Metal build, no unsafe), but talk needs `whisper-cli` present: macOS = drive `brew install whisper-cpp` like the ADE (`audio.rs:3897-3975`) with a graceful hint when Homebrew is absent; Windows = reuse the pinned v1.8.4 zip + sha256; Linux = PATH-only hint. Version skew of user-installed whisper-cli is possible — tolerate warning-line noise on stderr (`audio.rs:4114-4130`) and treat exit≠0 stdout/stderr as the error message.
4. **Deepgram key security** [V/I]: do NOT copy the ADE's localStorage precedent. Vault it (FileVault + SecretWire, UDS-only), never log it (redact in `daemon.log` and any diagnostics), cap 512 chars/no control chars (`audio.rs:4337-4349`), validate via `GET /v1/auth/token` before saving. Remember pricing is per-minute streamed — an accidentally-stuck-open WS costs money; enforce a hard session cap (ADE uses 900 s capture cap / 90 s stream result timeout).
5. **Non-streaming Deepgram models** [V-docs]: `/v1/models` includes `whisper-*` (batch-only) and Flux lives on `/v2/listen` — the model picker must filter `streaming:true` and exclude Flux for dictation, or route non-streaming picks through prerecorded REST on commit (worse UX; recommend filter-only for T-wave).
6. **Frozen-contract ceremony** [V]: any new frames/features require golden-fixture regeneration and hit the CI test-count ratchet; budget for it. Keep v1 wire surface to the single secret RPC (or zero, with the 0600-file fallback) to stay light.
7. **Terminal rendering edge cases** [I]: some fonts lack partial blocks (rare in dev terminals); provide a plain `#`/`|` fallback wave style flag. 30 fps redraw is within the existing dirty-tick budget; don't add a second timer.
